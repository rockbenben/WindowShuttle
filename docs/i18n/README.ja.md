# WindowShuttle

> ドラッグせずにモニター間でウィンドウを移動 — 1つずつでも、画面全体でも

**別のモニターへウィンドウを移すために、デスクを横切るような長いドラッグをする必要はありません。** `Ctrl` と右ボタンを押しながら目的の画面の方向へ軽くフリックするだけで、カーソルの下にあるウィンドウはすでにそこに移動しています。画面全体を動かしたいですか？ショートカットキーを1回押すだけで、現在いる画面とメイン画面の全ウィンドウが入れ替わります。WindowShuttle はタスクトレイに常駐し、インストール不要ですぐに使えます。

- **狙うのではなく、払う（フリック）。** `Ctrl` + 右ボタンを押して画面に向かってサッと払い、離します。最初からその画面を指しているため、「何番目のモニターか」を考える必要はありません。間違えて飛ばしたら？ `Ctrl` + 中ボタンクリックで元に戻ります。
- **1つのウィンドウも画面全体も、同じツールで。** 7つのアクションが揃っています：現在のウィンドウを送る、2つの画面を丸ごと入れ替える、モニターを取り外した後に散らばったウィンドウを一括回収する。キーボード、マウス、トレイメニュー、CLI のいずれからでも操作可能です。
- **ジオメトリは再計算され、そのままコピーされません。** 異なる DPI や解像度の混在は例外ではなく標準のユースケースです。移動先画面に合わせてサイズは適切にスケーリングされ、最大化は最大化のまま維持され、最小化ウィンドウは新しい画面で復元され、スナップされたウィンドウは半分や4分の1の配置をそのまま保ちます。
- **マップ自体が操作パネル。** 上部のパネルには、デスク上での実際のサイズと配置でモニターが描かれます。カードから別のカードへウィンドウをドラッグするだけで移動できます。移動のたびにマップは自動更新され、現在の配置が常に表示されます。省略されたチップにカーソルを合わせるとフルタイトルが確認でき、ドラッグ中は受け入れ先のカードがハイライトされます。
- **制約なし、安心の設計。** 単一のポータブル実行ファイルで、インストーラーもアカウントも不要です。手動で更新を確認するか、起動時の更新確認を有効にしない限り、完全にオフラインで動作します。Windows 専用です。

## 動作環境・互換性

| 項目 | サポート状況 |
|---|---|
| **OS** | Windows 10 または 11 |
| **アーキテクチャ** | x64（公開ビルドは x64 のみ、ネイティブ ARM64 版はありません） |
| **.NET** | スタンドアロン版は不要。軽量版は [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) が必要 |
| **モニター** | 2台以上。画面間アクションには最低2台必要です。単一画面では「画面が1台のみ」または「移動対象なし」と応答し、何も移動しません |
| **混合 DPI / 解像度** | 完全対応。ピクセル単位の単純コピーではなく、移動先モニターに合わせてジオメトリを再計算します |
| **管理者権限のウィンドウ** | 移動するには WindowShuttle 自体も管理者権限で実行する必要があります。詳細は[既知の制限](#既知の制限)を参照 |

## ダウンロード

**[⬇ 最新リリースを取得](https://github.com/rockbenben/WindowShuttle/releases/latest)** —— Windows x64。

- **`WindowShuttle-<version>-win-x64.zip`** —— スタンドアロン版。.NET ランタイム内蔵、追加インストール不要、解凍するだけで動作します。迷ったらこちらをお選びください。
- **`WindowShuttle-<version>-win-x64-needs-dotnet10.zip`** —— 軽量版。アプリ本体のみで、PC に [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) がインストールされている必要があります。ダウンロードサイズが大幅に小さくなります。
- **`WindowShuttle.exe`** —— 上記軽量版の中身の単一 exe です。直接クリックして実行したり、既存の exe を上書きして更新できます。ランタイムが不足している場合は Windows がダウンロードを案内します。

すべて同じ単一ファイル `WindowShuttle.exe` であり、インストーラーも登録も不要です。唯一の違いは起動時のオーバーヘッドです。スタンドアロン版は起動ごとに一時フォルダーへ自己展開するため、ランタイム導入済みビルドより起動に少し時間がかかります（特に `list` のような1回限りの CLI 呼び出しで顕著です）。トレイ常駐時やショートカットキーの応答速度には一切影響しません。

本ソフトはコード署名を行っていないため、初回起動時に Windows SmartScreen の警告が表示される場合があります。**詳細情報 → 実行** をクリックしてください。

**エラー時のログ。** 操作中にエラーが発生した場合、アプリはクラッシュせず自動復旧して通知カードでお知らせします。詳細は `%APPDATA%\WindowShuttle\crash.log` に追記されます。問題が発生していない場合、このファイルは作成されません。

**アンインストール・削除方法。** インストーラーを使用しないため、通常の削除作業は exe をゴミ箱に入れるだけです。ただし1点だけ例外があります。「管理者として」自動起動を有効にした場合、**タスクスケジューラ**に登録されます。exe だけを消すと存在しないパスを指すタスクが残ってしまうため、**先に「Windows 起動時に実行」のチェックを外してください**（タスクとレジストリの両方がクリーンアップされます）。その後 exe と `%APPDATA%\WindowShuttle` フォルダーを削除してください。

## 7つのアクション

7つのうち6つはトレイメニューおよび CLI から実行可能です。「方向で送る」はマウスジェスチャ専用です（メニューやコマンドには方向がないため）。また「画面番号」ツールもトレイメニューと CLI に用意されています。初期設定で2つのショートカットキーと4つのマウスジェスチャが登録されています：

| アクション | ショートカットキー | マウスジェスチャ | 説明 |
|---|---|---|---|
| **画面をまるごと入れ替え** | `Win`+`Shift`+`X` | `Ctrl`+右ボタン左フリック | 現在の画面とメイン画面のウィンドウをすべて入れ替え。すでにメイン画面にいる場合は前回入れ替えた画面と入れ替え |
| **最前面どうしを入れ替え** | `Win`+`Shift`+`Z` | `Ctrl`+右ボタン右フリック | 両方の画面でそれぞれ一番手前にあるウィンドウだけを入れ替え |
| **メインへ送る** | *(未設定)* | *(未設定)* | 現在のウィンドウをメイン画面へ移動 |
| **次のモニターへ送る** | *(未設定)* | *(未設定)* | ウィンドウを右隣のモニターへ移動（一番右からは一番左へ循環） |
| **方向で送る** | *(ジェスチャ専用)* | `Ctrl`+右ボタンドラッグ | 目的の画面の方向へ払うと、カーソル下のウィンドウがその画面へ移動 |
| **すべて集める** | *(未設定)* | *(未設定)* | サブ画面にある全ウィンドウをメイン画面へ一括回収 |
| **元に戻す** | *(未設定)* | `Ctrl`+中クリック | 直前のアクションで移動したすべてのウィンドウを元の位置へ復元 |
| **画面番号** | *(未設定)* | *(未設定)* | 各画面の中央に大きく画面番号（「画面 1」など）を一時表示 |

マウスジェスチャは「押した瞬間にカーソルの下にあったウィンドウ」を対象とします。一方、キーボード、トレイメニュー、CLI は「現在アクティブ（最前面）なウィンドウ」を対象とします。

### マウスジェスチャ

マウスジェスチャはシステム全体で有効で、**ウィンドウをアクティブにする必要はありません**。動かしたいウィンドウの上にカーソルを置き、修飾キーを押しながら右ボタンドラッグするだけで移動できます。

修飾キーとトリガーボタンは設定で変更可能で、標準では **`Ctrl` + マウス右ボタン** です。短くクリックした場合は通常の右クリックとして動作し、コンテキストメニューが開きます。最小デッドゾーン（24 ピクセル）を超えてドラッグしたときのみジェスチャとして認識されます。

#### `Ctrl` + 右ボタンを押しながらフリック

- **目的のモニター方向へ払う：方向で送る。** カーソル下のウィンドウがその画面へ移動します。
- **左へフリック：画面をまるごと入れ替え。** 現在の画面とメイン画面のウィンドウをすべて入れ替えます。
- **右へフリック：最前面どうしを入れ替え。** 最前面のウィンドウ同士だけを交換します。
- **中ボタンを1回クリック（ドラッグ不要）：元に戻す。** 直前の移動を元の位置に戻します。

ジェスチャは物理的なマウス向けに設計されており、タッチパッドのマルチフィンガージェスチャには対応していません。

## 設定

メインウィンドウ下部の設定バー、およびタイトルバー右上の「更新」メニュー：

- **閉じた後もトレイで実行を続ける**（標準：オン）——閉じるボタンを押してもアプリを終了せずトレイに最小化します。
- **起動時に更新を確認**（標準：オフ、タイトルバーの「更新」メニュー内）——GitHub に最新リリースがあるか確認します。新バージョンがある場合は zip をダウンロードし、SHA-256 整合性を検証した上で案内します。実行中のファイルを強制上書きすることはありません。
- **Windows 起動時に実行**（標準：**オン**）——開機時に `--tray` 引数付きで静かにトレイに常駐します。
- **管理者として**（標準：オフ、「Windows 起動時に実行」の下）——通常のレジストリ自動起動を、**タスクスケジューラ経由の最高特権実行タスク**に切り替えます。初回チェック時に一度 UAC 画面が出ますが、以降は毎回のログオン時に昇格プロンプトなしでサイレント起動します。ポータブル単一ファイルにも完全対応しており、任意のフォルダーから登録可能です。

  これにより、UIPI による管理者ウィンドウの操作不能問題（管理者ウィンドウを動かせない、前面にある間ジェスチャが効かなくなる）が根本から解消されます。

- **モニター切断時に画面外のウィンドウを救出**（標準：オン）——ケーブル抜去やスリープ復帰時に、すでに存在しない座標に残された迷子ウィンドウを自動で可視エリアに引き戻します。
- **全画面表示アプリをスキップ**（標準：オン）——ゲームや全画面動画をプレイ中の画面を誤って入れ替えないよう、全画面アプリを自動で除外します。

## コマンドライン（CLI）

WindowShuttle は単一の実行可能ファイルです。常駐実行中にターミナルやスクリプト、ランチャーから呼び出すと、名前付きパイプ（IPC）経由で常駐インスタンスに指示を送り、結果を出力して即座に終了します。

常駐インスタンスがない場合でも、`WindowShuttle.exe list` と `--smoke` は自己完結して動作します。

| コマンド | 説明 |
|---|---|
| `WindowShuttle.exe list` | 各ディスプレイの幾何配置とウィンドウ一覧を JSON 形式で出力（読み取り専用） |
| `WindowShuttle.exe swap` | 現在の画面とメイン画面の全ウィンドウを入れ替え |
| `WindowShuttle.exe swap-top` | 現在の画面とメイン画面の最前面ウィンドウを入れ替え |
| `WindowShuttle.exe to-primary` | 前面ウィンドウをメイン画面へ送る |
| `WindowShuttle.exe gather` | サブ画面のウィンドウをすべてメイン画面へ集める |
| `WindowShuttle.exe to-next` | 前面ウィンドウを次の画面へ送る（右端からは左端へ循環） |
| `WindowShuttle.exe to <n>` | 前面ウィンドウを**第 n 画面**へ送る（n は左から順の画面番号 1, 2...） |
| `WindowShuttle.exe identify` | 各画面の中央に識別番号をフラッシュ表示 |
| `WindowShuttle.exe undo` | 直前の移動を元に戻す |
| `WindowShuttle.exe --tray` | トレイに常駐して起動（自動起動用） |
| `WindowShuttle.exe --help` | コマンド一覧とヘルプを表示 |

コマンド成功時の終了コードは 0 で、`{"action":"to-primary","moved":1}` のような JSON が標準出力に出力されます。権限不足などで失敗した場合は終了コード 3 と `{"error":"access_denied"}` を返します。

## 既知の制限

- **管理者権限のウィンドウ**：管理者権限のない WindowShuttle は、タスクマネージャー等の昇格ウィンドウを移動できません（Windows の UIPI 整合性レベル制限）。解決策：設定で「管理者として」自動起動を有効にするか、アプリを手動で管理者として起動してください。
- **前面の管理者ウィンドウとジェスチャ**：管理者ウィンドウがアクティブな間は低特権フックにマウス入力が届きません。アプリ自体の昇格実行で解決します。
- **全画面アプリの除外**：ゲームなどの全画面アプリは誤爆防止のため既定でスキップされます。移動したい場合は設定で無効化してください。
- **応答なしウィンドウのスキップ**：フリーズしているウィンドウは安全のためスキップされ、CLI 出力にその数が記録されます。
- **仮想デスクトップ**：別デスクトップにあるウィンドウは cloaked 属性が付き、意図的に除外されます。移動したい場合はその仮想デスクトップに切り替えてから操作してください。
- **物理座標とスナップ復元**：ディスプレイマップは実ピクセル座標に基づいて描画され、マルチモニターの隙間や縦置きも正確に反映します。アンドゥデータは `.pending` アトミック保存により保護されます。
- **ポータブル版の昇格自動起動**：ポータブル単一ファイルは任意の書き込み可能フォルダーから昇格自動起動タスクを登録できます。外側引用符付きの古いパスも自動正規化され、検証完了後に安全に登録されます。
- **更新検証**：更新チェック時は常にパッケージの SHA-256 チェックサムを検証し、UI スレッドを妨げることなく安全に処理されます。

## ソースコードからのビルド

.NET 10 SDK が必要です（Windows 専用）。

```bash
dotnet build WindowShuttle.sln -c Debug
dotnet test tests/WindowShuttle.Core.Tests
```

自己診断スモークテストの実行（常駐インスタンスに干渉しません）：

```bash
WindowShuttle.exe --smoke
```

単一ファイル版の発行 (win-x64)：

```bash
dotnet publish src/WindowShuttle.App -c Release -p:PublishProfile=win-x64
dotnet publish src/WindowShuttle.App -c Release -p:PublishProfile=win-x64-needs-dotnet10
```

発行後、`pwsh ./tools/package-release.ps1 -Tag vX.Y.Z -OutputDirectory <dir>` でパッケージ化とスモークテストの検証を実施できます。
